# 旧系统迁移

新版日常运行不需要 MySQL。此工具只在切换前读取一次旧库，不启动、修改或卸载旧数据库。

## 推荐：在程序内完成

1. 关闭旧程序的录入页面，暂时不要修改旧资料。
2. 打开“迁移旧资料”，点击“自动查找旧系统”；未找到时选择旧程序文件夹。
3. 勾选暂停旧录入的确认，点击“读取并核对资料”。缺少照片时按提示选择含 photos 的旧程序文件夹。
4. 服务未启动时可点击“检查旧服务”，用户确认后启动检测到的本机 MySQL/MariaDB 服务。权限不足时维护者协助一次；不自动提升权限。
5. 核对药品、处方、照片、日期和总金额，点击“开始迁移”。确认前仅创建临时校验副本，不写新库。
6. 完成后抽查处方照片，并导出完整备份。迁移前后自动备份，原系统保持不变。

旧系统密码只在本次主进程/后台线程内使用，不显示到页面、不写日志。编译 DAO 配置以实际调用参数识别；不支持的配置交由高级设置，不猜测密码。高级连接支持手动输入；照片目录单独选择。

下面的命令行导出仅保留为维护者备用路径，日常用户不需要安装 Node.js 或运行命令。

## 迁移前

1. 保存旧数据库完整备份、Tomcat 应用中的照片目录和旧程序。先在副本上试迁移。
2. 确认实际表和 DAO 一致：user、medicine、prescription、prescriptionMedicine、prescriptionPhoto。仓库没有 SQL schema，必须核对真实环境。
3. 暂停旧程序写入，使用仅有 SELECT 权限的账号导出；旧表可能不支持事务，运行中导出无法保证一致性。
4. 在有旧库访问权限的维护者电脑安装 Node.js 24+，在 desktop 目录执行 npm ci。

## 导出

连接配置通过进程环境变量传入：

| 变量 | 内容 |
|---|---|
| CLINIC_MYSQL_HOST | 默认 127.0.0.1 |
| CLINIC_MYSQL_PORT | 默认 3306 |
| CLINIC_MYSQL_DATABASE | 旧数据库名称，必填 |
| CLINIC_MYSQL_USER | 只读账号，必填 |
| CLINIC_MYSQL_PASSWORD | 当前终端安全输入，不写入仓库或脚本 |
| CLINIC_LEGACY_WEBROOT | 旧 Tomcat 应用根目录，包含 photos 子目录；有照片时必填 |

```powershell
npm run export:legacy -- C:/ClinicMigration/legacy-export.json
```

输出父目录须预先建立。工具拒绝覆盖已有文件、缺失照片、越界照片路径和不支持的图片格式，不会静默略过资料。支持 PNG/JPEG/WebP，每张最多 8 MB；单次 JSON 导入最多 256 MB。超过此体量时先由维护者扩展迁移方案，不能截断导出。金额按分四舍五入，核对旧浮点金额的舍入差异。

不会导出用户密码。导出文件包含病历和照片，应按原资料同等方式保管，不提交到 Git。

## 导入与核对

1. 在桌面应用的空库中点击“备份与设置 → 导入旧系统资料”。如已添加正式数据，不允许覆盖或混入，应先备份并安排合并。
2. 选择导出 JSON，确认后导入。事务失败会全部回滚，可修正原数据后重试。
3. 对照导出终端的药品数、处方数、照片数和总金额；抽查早期/近期处方、月末数据、中文和照片。
4. 旧系统药品表只保留当前价格。旧处方总额保持原值，明细标注“迁移时价格”。修改数量后按明细计算新的金额，仍保留迁移来源标识。
5. 导出新版完整备份，在独立测试账户或测试电脑执行恢复、抽样查询和照片查看。
6. 核对通过后再切换日常使用。旧系统及原始备份保留，直至维护者确认回退窗口结束。

## 回退

切换前可继续使用原系统。切换后如果新版已有新增处方，先导出新版备份并列出新增记录；不能直接回到旧库而忽略新增资料。本次未实现双向同步。
